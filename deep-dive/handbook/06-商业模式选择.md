# 06｜商业模式选择：不是只有“自己干”或“加盟”

> 核心问题：价值如何被生产、交付、收费，并最终留下利润？
>
> **什么时候回到本章**：考虑加盟、代理或更换收费方式，业务高度依赖某个平台、供应商或 API，或者免费试用的人很多却没人真正付费的时候。

## 商业模式是多个选择的组合

至少检查：

- 产品 / 服务 / 内容 / 平台；
- To C / To B / To G 等不同购买主体；
- 自营 / 加盟 / 代理 / 分销 / 合作；
- 自制 / 采购 / 撮合；
- 线上 / 线下 / 混合；
- 一次收费 / 订阅 / 按量 / 抽佣；
- 高客单低频 / 低客单高频；
- 平台流量 / 私域 / 自有渠道；
- 重资产 / 轻资产。

## 选择标准

早期不要问“哪个模式最高级”，问：

- 哪个最容易验证？
- 哪个最符合当前资源？
- 哪个现金压力更低？
- 哪个交付可控？
- 哪个风险可承受？
- 哪个最容易获得第一批真实交易？

## 加盟/代理四问

如果借用别人的系统，至少核实：

1. 前期到底交什么钱、压什么货、最低采购多少？
2. 退款、售后、坏账由谁承担？
3. 佣金/利润何时结算，有什么扣减条件？
4. 退出时库存、未结款、客户归属怎么处理？

所有关键承诺尽量落到书面材料与合同，不靠口头保证。

## 免费验证和付费验证不是一回事

免费可以验证：

- 有没有人愿意试；
- 是否愿意花时间；
- 交付是否有效；
- 使用过程哪里有问题。

但免费不能单独证明支付意愿。

如果当前最危险的假设是“用户会不会付钱”，实验里必须出现真实价格、真实取舍和真实交易行为。

## 关键依赖方
列出平台、供应商、软件/API/模型、支付渠道、上游厂商和核心合作方。逐个问：涨价、封号、停服、改规则会怎样？有替代吗？客户和数据归谁？

## 本章工具

- `tools/06-价值主张卡.md`——用一句话写清为谁、在什么场景、解决什么问题、通过什么方式、带来什么结果，并列出最危险的三个假设和承诺边界
- `tools/06A-关键依赖风险表.md`——列出平台、供应商、API 等关键依赖的失效后果、替代方案和客户/数据归属，找最大单点故障和最低降险动作

## 通关条件

- [ ] 能画出“谁付钱—谁得到价值—谁负责交付—钱如何流动”
- [ ] 已比较至少两种可行模式
- [ ] 知道当前为什么先选这一种
- [ ] 对不可逆承诺已有核实计划
