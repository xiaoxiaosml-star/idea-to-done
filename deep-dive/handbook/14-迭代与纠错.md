# 14｜迭代与纠错：创业不是一直坚持，是不断缩短犯错时间

> 核心问题：当结果不好时，怎么知道该改什么，而不是乱改？
>
> **什么时候回到本章**：结果不好却不知道该改什么、同一个错误第二次出现，或者情绪上想全推翻重来的时候。

## 标准循环

**假设 → 行动 → 数据 → 复盘 → 判断 → 修改 → 新实验**

## 复盘五问

1. 原来假设什么？
2. 实际发生什么？
3. 哪条证据最重要？
4. 差异可能来自哪里？
5. 下一轮只改什么？

## 错误日志

记录真正重要的误判：

- 当时怎么判断；
- 根据什么；
- 后来什么证据推翻；
- 错误属于信息不足、逻辑错误、执行偏差还是环境变化；
- 以后如何更早发现。

目标不是少犯所有错误，而是避免同类错误高成本重复。

## 何时改方案，何时改目标

方案失败一次，先换方案。

多个不同方案在足够样本下都失败，而且共同指向同一基础假设错误，才考虑返回需求、用户甚至念头层。

## 常见错误

- 一轮改多个变量：价格、文案、人群、渠道同时改，结果好坏无法归因。一次只改一个关键变量，改不了全部时至少记录哪些变了。
- 结果不好就凭情绪改：没有证据的修改只是另一种赌博。先走完复盘五问，差异来源不清时先做最小判别实验。
- 方案失败一次就返回需求层：换方案优先；多个不同方案在足够样本下都失败、共同指向同一基础假设错误，才考虑返回念头层。过早跳关会让验证反复重来。
- 不记错误日志：同样的误判会以更高成本重复第二次。只记真正重要的误判：当时怎么判断、根据什么、被什么证据推翻、以后如何更早发现。
- 复盘只挑支持自己的证据：验证的目标是尽早暴露错误假设，不是凑支持票。证据表要同时记录支持、反对和目前无法解释的证据。
